### Bowerloom

<picture>
  <source media="(prefers-color-scheme: dark)" srcset="assets/bowerloom-wordmark-cream.svg">
  <img src="assets/bowerloom-wordmark-ink.svg" alt="Bowerloom" width="280">
</picture>

Bowerloom combines portable agent teams with reviewable workflows and explicit approval. Define roles, skills, and permissions in readable files outside any individual agent app.

Its prepared GitHub workflow binds approval to the proposed change before a write and records the work. Publication and merging remain separate decisions.

The public source includes a local alpha trial. Read the current evidence and setup instructions before you depend on a capability. A public repository does not mean a hosted service or general release is available.

[Explore Bowerloom](https://github.com/sageadvicellc/bowerloom) · [Read the evidence and limits](https://github.com/sageadvicellc/bowerloom/blob/main/docs/alpha/acceptance-status.md) · [Follow the release plan](https://github.com/sageadvicellc/bowerloom/blob/main/docs/transition/release-plan.md)

## Help the work grow

Start with the README in the project that interests you. For Bowerloom, the [working order](https://github.com/sageadvicellc/bowerloom/blob/main/docs/transition/working-order.md) explains contribution and review expectations.

- [Report a Bowerloom issue](https://github.com/sageadvicellc/bowerloom/issues) with a small example and the result you expected.
- [Ask a Bowerloom question](https://github.com/sageadvicellc/bowerloom/discussions) or share what you are trying to build.
- Propose a focused change with enough context for someone else to review it.

Use fictional examples in public reports. Keep credentials, customer data, and private business records out of issues and pull requests.
